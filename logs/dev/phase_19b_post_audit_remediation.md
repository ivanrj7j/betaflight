## 1. High-Level Executive Overview & Silicon Context

Following the post-Phase 19 audits ([07_POST_PHASE_19_DEEP_AUDIT_AND_DEBT.md](../../knowledgebase/code_audit/07_POST_PHASE_19_DEEP_AUDIT_AND_DEBT.md), [08_WIDTH_AND_DEPTH_AUDIT_POST_PHASE_19.md](../../knowledgebase/code_audit/08_WIDTH_AND_DEPTH_AUDIT_POST_PHASE_19.md), [09_PHASE_19B_SILICON_PURPLE_LED_REGRESSION.md](../../knowledgebase/code_audit/09_PHASE_19B_SILICON_PURPLE_LED_REGRESSION.md)), physical bench logs isolated four interacting root causes:
1. **`FLASHER` vs. Raw `COM9` Terminal Behavior (`audit19.4.txt` vs. `com9_output.txt`):** Bypassing the host flasher serial console with [`tempfiles/read_com9.py`](../../tempfiles/read_com9.py) produced a clean `791`-line `Phase 19` (`68b2f5f32`) capture ([`tempfiles/com9_output.txt`](../../tempfiles/com9_output.txt)), including boot banners, `version`, `status`, `help`, `exit`/`save` reboots, and full `451`-line `dump`.
2. **Polled `UART_IIR_FCR` Read Desync (`audit19b.1.txt`) & `Erratum 11` Purple `LD1`:** Re-introducing `UART_IIR_FCR` reads inside `uartIrqHandler()` (which executes both in IRQ context and in polled mode via `uartRead()` -> `uartPlatformPollRx()` and `taskHandleSerial()` -> `uartPollRx()`) triggered the historical Phase 13.4 / Audit 02 DW_apb_uart receiver status desync (`# s`, `# _`, then frozen RX in [`tempfiles/audit19b.1.txt`](../../tempfiles/audit19b.1.txt#L83-L87)), while [`tempfiles/read_com9.py`](../../tempfiles/read_com9.py) also blocked 50 ms per keystroke via `ser.read(4096)`. Meanwhile [`tempfiles/audit19b.2.txt`](../../tempfiles/audit19b.2.txt) confirmed `LD1` Purple was eliminated (`LD4` `PROC_HB` blinking yellow) and `.noinit` `save` retained `battery_profile 1` cleanly across warm reboot.
3. **Cold-Boot `.noinit` `persistentObjects[]` Initialization Gap:** Enabling `PERSISTENT` (`.noinit`) + `USE_PERSISTENT_OBJECTS` without invoking `persistentObjectInit()` during startup left `persistentObjects[16]` uninitialized with random SRAM bits on cold power-up.

## 3. Code Implementation Rationales

* **[stub_drivers.c](../../src/platform/ARIES/stub_drivers.c) & [serial_uart_aries.c](../../src/platform/ARIES/serial_uart_aries.c) (`Erratum 11`, Phase 13.4 & `H22`):** Parked `OWNER_FREE` pins (`0..DEFIO_IO_USED_COUNT - 1`) in High-Z input (`IOCFG_IN_FLOATING`) so active-LOW `LD1` (`PA23`/`PA24`) stays OFF; claimed `OWNER_SERIAL_TX`/`RX` via `IOInit()` in `uartPinConfigure()`; removed the polled `UART_IIR_FCR` read from `uartIrqHandler()` (matching C-DAC `HardwareSerial::handleRxInterrupt()` & Phase 13.4 so DW_apb_uart `LSR & 0x01` never desyncs); wrapped `uartEnableTxInterrupt()` under `thejas32_atomic_enter()`/`exit()` while keeping `ETBEI` (`0x02`) strictly `0` (`H22`); wired `1 kHz` `uartPollTx()` in [tasks.c](../../src/main/fc/tasks.c) `taskMain()`; and switched [`tempfiles/read_com9.py`](../../tempfiles/read_com9.py) to non-blocking `ser.in_waiting` + full `msvcrt.kbhit()` drain.
* **[system.c](../../src/platform/ARIES/system.c) & [pwm_motor_aries.c](../../src/platform/ARIES/pwm_motor_aries.c):** Added `__attribute__((weak)) ariesPwmEmergencyStop()` (strong in `pwm_motor_aries.c`) across `handle_trap_panic()`, `systemReset()`, `systemResetToBootloader()`, `failureMode()`, and `ariesPwmMotorShutdown()`; added active-pulse (`Control & 0x01`) + rollover-safe `motorPwmRate` gating (`2500 us` @ `400 Hz`); added `__attribute__((weak)) persistentObjectInit()` in `system.c` (overridden by `stub_drivers.c`) called from `systemInit()` so cold-boot `.noinit` `persistentObjects[16]` zeroes stale SRAM while preserving `'Bef1'` warm resets; gated boot banners behind `ARIES_DEV_LOGGING > 0`; and halted `BOOTLOADER_REQUEST_ROM` / `failureMode()` safely with `__WFI()`.
* **[bus_spi_aries.c](../../src/platform/ARIES/bus_spi_aries.c) & [exti_aries.c](../../src/platform/ARIES/exti_aries.c):** Initialized SPI0 `hw->Control` to Mode 3 (`THEJAS32_SPI_CTRL_MODE_3 << THEJAS32_SPI_CTRL_MODE_SHIFT`) matching `leadingEdge == false`, and enforced `IOCFG_IN_FLOATING` in `EXTIConfig()`.
* **[platform.h](../../src/platform/ARIES/include/platform/platform.h), [target.h](../../src/platform/ARIES/target/ARIESV3/target.h), [ARIES.mk](../../src/platform/ARIES/mk/ARIES.mk), [aries_v3.ld](../../src/platform/ARIES/link/aries_v3.ld), [build_verify.sh](../../src/test/unit/aries/build_verify.sh), [timer_def.h](../../src/platform/ARIES/timer_def.h), [bootstrap_diag.c](../../src/platform/ARIES/bootstrap_diag.c):** Enabled `PERSISTENT __attribute__((section(".noinit")))` + `USE_PERSISTENT_OBJECTS`, `UART_TX_BUFFER_SIZE 512`, `DMA_DATA __attribute__((aligned(4)))`, `-mstrict-align`, parameterized `ARIES_DEV_LOGGING ?= 1` gating `USE_IMMEDIATE_CLI`, accurate `PA22` `LD1_4 Green` docs, `242K` (`0x0023E7FF`) SRAM clamp with `_stack_size >= 0x2000` assertion, and synced `bootstrap_diag.c` / `timer_def.h`.
